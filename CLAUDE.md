# Maestro

Autonomous engineering agent that resolves gaps a human or CI raises, under human approval. Built on Claude Agent SDK; runs an autonomous loop **act → reflect → dream → evolve**, with all self-modifications requiring human approval.

Quick-start: [README.md](README.md); CLI usage: [docs/cli.md](docs/cli.md); module-by-module table: [docs/modules.md](docs/modules.md).

> **Document discipline.** An at-a-glance orientation, not an encyclopedia. Each invariant is one line: a load-bearing rule plus a pointer to code or `docs/`. Don't restate constants, rule bodies, registry contents, or incident histories — code is the spec; `docs/` explains. Proposal docs cite symbols/sections, never `file.py:line` (`tests/test_no_line_citations_in_docs.py`).

## Architecture orientation

- **Core loop** — `maestro/agent.py` (`run`, `contemplate`, `evolve`, `generate_task`, `_run_task_phase`, `_audit_self_model`, `run_loop`); collaborators: `maestro/loop/`.
- **State & memory** — `maestro/{consciousness,journal,memory,task_queue}.py`.
- **Execution & SDK** — `maestro/{sdk,executor,planner,tools}.py` plus `maestro/prompts/`.
- **Surfaces** — `maestro/{dashboard/,notifications/,email,email_tools,telegram_tools,plan_decision,messaging,issues,crash}.py`.
- **Infra** — `maestro/{config,toml_config,migration,fileutil,search,types,cost_tracking,task_cost_gate,remediation_tracker,escalation_bridge,contributions,diagnostics,health_check,stats,audit_checks,gate_check,red_root,deed_ledger,logs,cli}.py`.
- **Code review** — separate `maestro_review/` package; see [`maestro_review/CLAUDE.md`](maestro_review/CLAUDE.md).
- **Paced CLI SDK** — separate `maestro_sdk/` package (CLI-driving SDK with paced keystrokes, distinct from `maestro/sdk.py`); see [`maestro_sdk/README.md`](maestro_sdk/README.md).

### Architecture invariants (load-bearing — read before changing)

- **Human-in-the-loop evolution** — Code changes require dashboard/Telegram approval; Bash is action-gated against PR/push bypass in-process and in `cli_paced` subprocesses via `maestro/tool_gating.py`, covering the task-execution *and* implementation lineages alike (the impl session plus the sessionless `implement` / `self_review` / `auto_fix` arms, each scoped by `make_task_tool_hooks` to the plan's own evolve branch), since a provider derives the gate from `QueryOptions.hooks` — so declaring a phase gated binds to installing it, via `tests/test_capability_gating.py` and the `action_gate_installation` structural guard; own-PR branch-writes derive from one AST-enforced oracle (`maestro/pr_facts.py`), whose push 'delivered' binds same-turn to `verify_push_advanced_remote_head` (a remote branch-head advance, not `is_pr_settled` ancestry), not the push return; `gh pr close` is permitted as reversible disposal (`permits_pr_close`), distinct from the blocked merge/ready/open bypass; the same gate refuses outward acts needing Thomas's identity — `gh repo`/`release`/`secret` writes, outward mutating `gh api` calls, and tag pushes; under `allowed_push_remotes` it also refuses a push to any remote but the task's own repo as `push-remote-foreign`.
- **Dashboard as thin status layer** — Dashboard only writes plan status (approve/reject/feedback), publication approve/reject, and messages; heavy work runs in the loop container.
- **Journal over logs** — the journal holds only inner thought the model wrote itself: `Journal.write_thought` admits just the `InnerThoughtSource` seams (a typed literal, refused at runtime, pinned by an AST test in `tests/test_journal.py`), because its tail feeds the planning prompts; every record a code template writes (deploys, merges, lifecycle, plan bookkeeping, audit findings, task outcomes) goes through `Journal.record_event` to `events.jsonl`, which no prompt reads, and operational rows written before the split are routed there on read.
- **File persistence** — JSON via `atomic_write()`; JSONL is append-only; read-modify-write uses `file_lock()`, and an append to a JSONL file any path rewrites takes that same `file_lock` (advisory `flock` excludes only writers who take it, so an unlocked append inside a rotation is lost to the rename); a self-model read-modify-write routes through `Consciousness.mutate_self_model` (`file_lock` across re-read → callback → write; the blind `save_self_model`, and the write with which `load_self_model` seeds a default, hold the same lock so an unmigrated caller still serialises); a read-modify-write that spans an SDK call, as the task queue's curator does, routes through its backend's atomic `mutate` (`file_lock()` RMW on JSON, one `BEGIN IMMEDIATE` on SQLite) and rebases onto the re-read live queue, so a concurrent `pop_head` is never erased by a stale replacement; all text I/O is UTF-8 (AST-enforced in `tests/test_memory.py`). `get_recent_tasks` bounds corrupted-record skipping so a corrupted tail can't force a full-file walk.
- **Tiered-memory archive** — Dream cycles split `task_history.jsonl` / `evolution_plans.jsonl` plus the telemetry sidecars `cost_samples.jsonl` / `usage.jsonl` into hot + cold siblings via `Memory.archive()` (the threshold must exceed the longest window any hot read covers, so no hot read loses recent rows to cold; plan rotation is additionally status-scoped to finished, unreferenced history — `ARCHIVABLE_PLAN_STATUSES` is its sole owner, so an unfinished or unrecognised plan status, and a slice of a proposal outside `FINISHED_PROPOSAL_STATUSES`, stays hot at any age; `failed` rotates only once its `failure_count` has spent the retry budget the caller passes in, `rejected` only once `rejection_learned`, a retired `rejected`/`obsolete` row whose PR is open (or whose PR state is unknown) stays hot for Tend, all decided by `_plan_row_archivable`; a task row cited as `source_task_id` by any plan `Memory._plan_row_stays_hot` keeps hot — the one lifecycle and date predicate both archive passes share — or as `task_id` by a publication proposal outside `FINISHED_PUBLICATION_STATUSES` stays hot); `journal.jsonl` is deliberately excluded (journal over logs), as is `events.jsonl` (the rejection learning idempotency check reads its full history). Cold storage is operator-managed, never read by hot paths.
- **Self-model archive** — entries dropped at the save door (`MAX_LIST_ITEMS`, `reason` `cap_overflow`) or evicted by an `update_self_model` reply (`replaced`, appended after the persist) land in `self_model_archive.jsonl`; `Consciousness.load_archived_items()` reads the tail. `open_questions` is exempt (bucketed sub-caps).
- **Restatement gate** — `detect_restatement` blocks self-model list items above a content-word Jaccard threshold; `_is_compound_item` rejects multi-concept labels; zero-cost. The plan duplicate and theme-cluster guards (`find_duplicate_pending_plan` / `find_theme_cluster_pending_plans`) compare against every live plan (`LIVE_STATUSES` via `get_live_plan_records`, proposal 100), so `approved` and `implemented` plans are covered — `find_duplicate_pending_plan` runs `is_plan_restatement` over that live corpus; `submit_for_review`'s rejection cooldown (M1) loop additionally runs it over plans rejected within `_REJECTION_COOLDOWN_DAYS`, so a resubmission whose title differs but whose content overlaps a recent loser above the same Jaccard threshold is refused via that cooldown path, not only when the title matches exactly. `submit_for_review` also refuses (obsolete, same refusal path) a plan whose `source_task_id` is already cited by a live (`pending_review`/`approved`/`implemented`, mirroring `LIVE_STATUSES`) plan (`is_source_task_recited`) — catching a restatement that reuses a stranded branch under fresh framing, which the content-word Jaccard guards miss. It likewise refuses (same path) a plan touching `maestro/cli.py` whose proposed CLI tokens are all already registered in `cli.py`, grounding a proposal for fresh CLI surface against the shipped tree (`_shipped_cli_surface` walks `add_argument`/`add_parser` with `ast`, binding each flag to its *owning subcommand* via the parser variable, so a `--flag` proposed for a subcommand that lacks it is novel even when another subcommand registers it; `_cli_grounding_verdict` refuses only when every proposed subcommand name, every flag bound to the subcommand it targets, and every global flag is already shipped) rather than the plan corpus. The inverse grounding also holds: it refuses (same reversible obsolete path) a plan whose *rationale cites* a `maestro <token>` CLI subcommand as established evidence when that token is neither shipped nor introduced by the plan's own `maestro/cli.py` change (`_cited_cli_tokens` mines hyphenated `maestro <token>` invocations — in prose or inside backticks, with the `maestro` prefix required so bare hyphenated concept names aren't swept up — and `_evidence_cli_grounding_verdict` reuses `_shipped_cli_surface`), closing the premise where a sensor is cited as established evidence while it lives only on an unmerged branch.
- **Identity context in every call** — Self-model injected as `system` prompt via stable + volatile slabs in `Consciousness.get_identity_prompt()`. Volatile fields (`evolution_count`, `open_questions`, `limitations_known`) MUST NOT enter the stable slab. AST-enforced in `tests/test_identity_prompt_slabs.py`; template enforcement in `update_self_model()`.
- **One objective system prompt** — `OBJECTIVE_PROMPT` in `maestro/prompts/defaults.py` is the only framing: `select_objective_prompt` / `resolve_framing_prompt` / `evolution_slot_system` return or prefix it; the identity slab is untouched.
- **Context bloat caps** — Every list/string entering a prompt has a load-bearing cap. Opt-in `[models] long_context` raises diff/file caps at `self_review` and the `converge_to_green` fix step (both keyed off `_long_context_active`); `[loop] long_context_implementation_enabled` extends to Session C/Executor. Long-context calls inject `LONG_CONTEXT_BETA`; Anthropic-only.
- **Tool-result frame cap** — a single tool-result must stay under the 1 MiB message frame the SDK transport will encode, so every `.py` file on disk under `maestro/`/`tests/` stays below `SPLIT_BUDGET`, set well under a ceiling derived from that frame and the measured encoding expansion — one assertion in `tests/test_source_file_size.py`, no per-file pins; a file is flagged at `SPLIT_DUE` first and the cure is a concern split, never a trim; ceiling, budget and bands owned by `maestro/source_budget.py`; an overflow is deterministic, not transient, and `_classify_error` keeps it out of `CLI_CRASH`.
- **Schema normalisation on startup** — `ensure_schema()` compares SHA-256 fingerprints; on a mismatch it advances the stored fingerprint and the dataclass loaders normalise each row on read rather than rewriting state files. Four genuine steps that move data still run unconditionally (`migrate_backfill_hashes`, `_seed_self_model`, `move_leak_cost_samples`, which moves the leaked test cost rows `cost_tracking.LEAK_FENCE` matches to `cost_samples.cold.leak.jsonl`, and `gap_store.carry_legacy_gap_rows`, which carries the gap ledgers out of a retired `charter.db` once).
- **Task-anchored evolution** — Plans prefer recent successful task branches via `EvolutionPlan.source_task_id`. `priority` is descriptive only — no built-in deferral gate. Bug triage stays human: only a `gap:maestro` label applied by an `operator_github_logins` login becomes evolution fuel.
- **Task branch isolation** — `run()` creates `maestro/task/{task_id}` branches; artifacts in `artifacts/{task_id}/` (gitignored). Kept branches may be re-used as evolution-PR base via `source_task_id`, falling back to fresh-from-`main` on conflict or pruned branch. `check_merge_clean` stamps `merge_clean` at completion and auto-directs clean-branch promotion.
- **Step dependency graph** — `PlanStep.depends_on` declares deps; `_build_execution_groups()` topo-groups with `asyncio.gather()`, gated by `sdk_max_concurrent_queries`; a step dispatches only once its prerequisites are `done`, so a failed prerequisite leaves its descendants `pending` (counted skipped).
- **MCP servers** — 2 external (Context7, read-only Serena) via `[mcp]` TOML need `remote_mcp`; the Fetch server is retired and Maestro has no web reach; GitHub goes through the `SubprocessCodeHost`, never an MCP server, so no MCP tool that writes to the repo can bypass the `Bash`-scoped action gate; Serena's mutating/exec tools are denied by name via `external_mcp_disallowed_tools` so it stays retrieval-only. 5 in-process introspection servers in `cli._build_agent_tools()`; enabled external launchers are PATH-checked fail-loud at `_build_agent`/`preflight`.
- **Bidirectional messaging** — Maestro↔Thomas via `messages.jsonl` (`reply_to` threading); inbound Telegram updates are `chat_id`-authorized before dispatch, since `get_updates` exposes the bot publicly; a Thomas `plan_feedback` message (a Telegram reply carrying a plan marker, or a dashboard "Request changes") is folded into that plan's `reviewer_feedback` ledger and never enqueued ([docs/self-evolution.md](docs/self-evolution.md#reviewer-feedback-on-pending-plans)); a Thomas reply threaded to a `[gap-decision #N]` question is applied by `evolution_fuel.apply_gap_decision` and never enqueued.
- **Standby & peak-throttle** — Standby skips iterations during configured UTC hours; peak-throttle (IANA-tz) tightens the burn-rate budget to slow the loop, not phases. See [docs/loop-lifecycle.md](docs/loop-lifecycle.md).
- **Fail loud — no warning-silencing exception handlers.** A broad `except` that logs-and-falls-through at warning level or above (or empty — `pass`, bare `continue`/`break`) — or a broad `contextlib.suppress(Exception)`, which is `except Exception: pass` by construction and so flagged on breadth alone — is forbidden outside the allowlist, and each allowlist entry's exempted handler count is pinned (`_ENTRY_HANDLER_BASELINE`) so exemptions can only shrink; swallows logging only at `debug`/`info` (and the functional `logger.log(level, ...)` form, whose level the AST cannot read) are a deliberate best-effort carve-out resting on human review, itself ratcheted per file by `_DEBUG_SWALLOW_BASELINE`; an entry may additionally anchor its rationale to a `docs/` section (`_ENTRY_DOC_ANCHOR`), validated to resolve so the justification cannot be deleted or renamed out from under a standing exemption. AST-enforced in `tests/test_no_silenced_exceptions.py`. Classify transient SDK failures via `_TRANSIENT_SDK_CATEGORIES`, else crash loudly into `crash.py::handle_crash`.
- **Gap store and taint owners** — `gaps.db` is opened only by `gap_store.build_gap_store` (WAL), and registered external text enters a prompt only as `taint.mark_untrusted`'s fenced `UntrustedText`, with `QueryResult.untrusted_input` stamped by the SDK seam for a call whose prompt or system held a registered UNTRUSTED fence (tool-result text is not yet covered, so `False` is not "clean"); AST-enforced by the `gap_store_owner` and `taint_owner` entries in `tests/structural_guards.py`.
- **Retired concepts stay retired** — `RETIRED_CONCEPTS` (`tests/structural_guards.py`) declares each retired concept with its identifiers, literals and the few exempt sites; `tests/test_retired_concepts.py` fails on any reference under `maestro/` outside them (proposal 148).
- **Main-phase SDK calls must be session-attached** — every loop phase calls Claude through `query_on_session(session, ...)`; bare `query()` is reserved for the documented `else` branch and tests. AST-enforced in `tests/test_structural_guards.py`.

### Subsystem invariants (one-liner per topic — deep dives in `docs/`)

**Loop & resilience** — see [docs/loop-lifecycle.md](docs/loop-lifecycle.md), [docs/sdk-internals.md](docs/sdk-internals.md):

- Resume-in-place for transient SDK failures; a rate-limit failure ceiling hands off to extended-idle probing. A warning hold gate pauses the loop on sustained per-call warning saturation above a utilization ceiling, waiting for the reported window reset (else probing at exponential backoff).
- Burn-rate throttle stretches sleep + gates the heaviest LLM phases at `[loop] max_loop_budget_usd_per_hour`. `budget_throttle_active` unions burn-rate and operator maintenance (Telegram `/maintenance`); under it the iteration counter freezes, and cadence phases dedup via `_last_phase_iteration` so frozen ticks don't re-fire.
- Graceful shutdown finishes the current phase before exit; `run_task` too despite popping its item first, relying on `stop_grace_period`. `_safe_shutdown_wait(timeout)` guards non-SDK shutdown waits against residual `CancelledError` from SDK teardown orphans.
- Task checkpointing — `run()` snapshots step-group progress to `checkpoints/<id>.json` (owned branches only), resumes on entry while the branch survives, clears on record, startup-swept; manual `resume-task <id>`.
- Stream-idle safety net via `asyncio.wait_for([sdk] stream_idle_timeout_seconds)` plus early-exit predicates for text/JSON callers.
- Up to four persistent sessions per iteration (A–D) plus ephemeral phase sessions; `run_task` uses none (`run()` opens its own). Sessions carry their creation-time prompt; specialized-prompt callers prepend it on `query_on_session`.
- `tend_evolution_prs()` is top-priority and **purely mechanical** (no SDK/burn-rate gating): merges `origin/main`, reminds, runs gates, reconciles orphans — for every open PR, after its plan leaves `implemented`/retired. A local `main` ahead of `origin/main` by only already-pushed commits is hard-reset and tended. LLM-judgment PRs → `pending_pr_requests` oldest-first; unresolved threads and overflow findings → remediation tasks.
- Tend's catch-up/conflict-route decision keys on *measured* `commits_behind` / `merge_tree_conflicts` (`pr_facts.observe_pr_staleness`), not the async host `mergeStateStatus` proxy, so a behind-but-clean PR the proxy masks still reaches the catch-up merge.
- `run()` is the primary deliverer of remediation fixes and recorded review-thread replies (pushed to `PendingPRRequest.pr_branch` before the completeness gate); Tend PR is the fallback. `_tend_single_pr` defers main-merge on pending CI, routes failing heads via `quality_gates_routed`, gates pre-merge `reset_hard`, rewinds post-merge, and bypasses conflict-cooldown on documented escape hatches; the ready-for-review ping is CI-gated.
- Post-session landing actuator (`session_landing.py`, `[loop] session_landing_enabled`, default-off) — before verdict composition, `_run_session_landing` commits+pushes gate-clean owned-branch edits (rewind on own red, hold the tree on an `INHERITED` red (a hold by the actuator only; the rest of the lap treats it as flag-off), oracle-gated; a failed or unconfirmed push is a typed `LandStatus`, never raised), then — only once the remote branch head is confirmed to advance — drops the merge-truth memo so the verdict grounds on a post-push `is_pr_settled` read.
- §5-push delivery-truth (`remediation_tracker.resolve_push_delivery_marker`, unconditional) stamps `Marker.OWNED_PUSH_AVAILABLE` + fire-or-close into an *empty* slot for an `OWNED_AHEAD` push failed/skipped, not the `AWAITING_TEND_PUSH` costume. The `_record_remediation_outcome` arm also pushes (`_push_owned_branch`) a gate-clean *uncommitted* edit or *committed-but-unpushed* head, red → rewind, never a red head.
- Addressed-thread auto-resolution (`[loop] resolve_addressed_threads_enabled`): the loop is the **sole** resolver — after a lap confirms both deliveries it resolves addressed AI-finding threads via `CodeHost.resolve_review_thread`. The remediation prompt's "Do NOT resolve any thread" contract is unchanged; a thread carrying a marker-less (human) reply is never auto-resolved.
- Remediation prompt prepends `prompts/remediation.py::merge_truth_first_preamble()`: `git fetch`+`--is-ancestor` then the OWNERSHIP-FORK `git rev-parse HEAD` vs `origin/<branch>` precede any status word (HEAD ahead ⇒ push owed); already-landed emits `partial`/`[stood-down]`, never `success`. Externally-blocked → may stand down; owned → land, push, or `gh pr close`. `classify_blocker_ownership` is the sole owned/external source (AST-enforced), `AWAITING_PUSH` owned.
- **Merge-truth chokepoint** — every PR-servicing face reads merge state through one provenance-stamped, fetch-first, per-iteration `is_pr_settled`, squash-merge-aware (host `mergedAt` or a matching local `VersionRecord` settles a not-ancestor read); AST-enforced sole door by `tests/test_structural_guards.py`; the verdict binds there, coercing a phantom not-landed stamp to settled.
- **CI-truth chokepoint** — CI status-check classification and check-log error-extraction have one owner (`ci_diagnosis`); `vcs`/`red_root` route through it, `read_run_log_failed` is the fetch carve-out, AST-enforced by `tests/test_structural_guards.py`.
- **Owed-act chokepoint** — what a PR owes right now (write code / hand off / wait for CI) has one owner, `pr_owed_act.py::classify_pr_owed_act`, which composes the ownership axis (`classify_blocker_ownership`/`classify_owned_blocker`) with the CI axis (`classify_ci_conclusions`); no scope may fold both axes into a private verdict and no module outside the owner may mint an `OwedAct` member as a produced value — a return, an assignment, or a call argument — while a comparison operand stays a read and `OwedAct(raw)` is the sanctioned round-trip, AST-enforced by `tests/test_structural_guards.py` regardless of any flag.
- **Transcript-reader chokepoint** — one parser owner (`maestro/logs.py`) for the provenance-stamped `.jsonl` SDK sidecars (default-on); AST-enforced by `tests/test_conversation_transcript.py::test_transcript_parse_owned_by_logs`.
- Dequeue gate chain (`_gate_pr_remediation_*`) zero-cost-evicts or skips a queued remediation on merged/landed/host-closed/stood-down/observed-ready/merge-block/costume-signature/repetition conditions (host-closed also routes its plan to `rejected`); a pre-pop `[ci-pending-hold]` yield (`[loop] ci_pending_hold_dequeue_enabled`, default-on) instead leaves an owned CI-pending-only PR queued, passing the slot to the next entry neither stalled nor held, else the queue head — and behind `[loop] ci_pending_green_handoff_enabled` (default-off) that same fire point first runs the demanding local gates (`diagnose_red_root`, ruff → mypy) and, when every one passes, delivers one `deliver_handoff` merge-or-close handoff under its own message naming that CI has not concluded (`ci_pending_green_handoff_message`, the `deliver_handoff` `message=` override) — a stand-down that arm alone also *releases* when CI later concludes RED, since ruff+mypy green is strictly weaker than CI green — its `has_standdown` read ordered ahead of the gate run so a PR already handed up pays for no subprocess, the run itself positioned on the PR branch by a checkout of a clean workspace, restored afterwards, and admitted only once the workspace reads that branch at `origin/<branch>`'s head (the runner measures the workspace tree, and this gate fires before any other checkout) and skipped — before any checkout — for an origin head already read RED, the yield itself unchanged; merge-block and stand-down share the classifier-derived `_tend_clearable_blockers` set; each stamps a bracketed reason, escalating once. Gates: [docs/loop-lifecycle.md](docs/loop-lifecycle.md).
- Stand-down writers — the LLM-narrated `[stood-down]` verdict (`_record_remediation_outcome`) and the zero-SDK mechanical actuator (`_dispose_mechanical_standdown`, for a stalled thread-clear lineage) persist to `stand_down_verdicts.jsonl`; eviction holds only while git-unlanded with a Tend-clearable blocker, and a new head auto-releases. Each record in the escalation ledger also stamps the `claim` it asserts (one per premise), and `maestro/standdown_validity.py` is the AST-enforced sole owner of that vocabulary (`StanddownClaim` / `StanddownValidity` / `assess_standdown_validity`) plus the zero-cost sensor naming a `handoff-ready` latch that a live `pr_owed_act` reading refutes — surfaced as `[standdown-refuted]` in `PR-LAPS` — the sensor itself releases nothing, it only names the vocabulary and surfaces the tag; the release actuator is `escalation_bridge.prune_refuted_standdowns` (`[loop] standdown_refutation_release_cap`, default-on, proposal 135), which consumes `assess_standdown_validity` to drop each refuted `handoff-ready` latch behind a withdrawal message.
- **Salvage oracle** — `assess_pr_salvage` is the single veto over give-up: a `SALVAGE_AND_LAND` verdict (unsettled, code-clearable blocker, non-disposable, within the reconcile budget — or, under `[loop] owed_act_binding_enabled`, unsettled and code-owed within that budget, disposable or not) blocks both stand-down writers and the orphaned-cure sweep and leaves the PR tend-eligible; only `DISENGAGE_PERMITTED` unlocks a `gh pr close` directive. Enforced by `tests/test_structural_guards.py`; it also gates the ahead-of-origin push guard, drought credit, and lap budget.
- `contemplate()` appends a self-suppressing `## Measured Behavioral Data` block (zero SDK cost) before `introspect`.

**Self-evolution** — see [docs/self-evolution.md](docs/self-evolution.md):

- **Task queue** — `generate_task()` curates `task_queue.json` capped at `[loop] task_queue_max`; `_run_task_phase` pops `pending_user_requests` → `pending_pr_requests` → head ([docs/self-evolution.md](docs/self-evolution.md#queue-head-selection)).
- **Task-anchored base** — `EvolutionPlan.source_task_id` nominates a kept task branch as implementation base, validated against recent task history.
- **Acceptance criteria** — up to 10 binding invariants (the schema asks for at least 1) extracted by `propose_plan()`, injected into `self_review` and the PR body; `types.py::validate_acceptance_criteria_count` is the sole owner of the 10-item cap ([docs/self-evolution.md](docs/self-evolution.md#acceptance-criteria-count-bound)).
- **Directive slot** — `SelfModel.next_task_directive` (one-shot, ≤200 chars) bridges contemplation → task generation; cleared inside `generate_task`'s curation pass (via `mutate_self_model`) once a response parses, even if every enqueue entry is gated out; survives SDK/parse failures; a concreteness drop rearms it.
- **Priority queues** — `pending_user_requests` / `pending_pr_requests` are FIFO queues bypassing `[loop] task_every`.
- **Audit rules** — `audit_self_model` runs twenty-one deterministic rules (`maestro/audit_checks.py`) at zero SDK cost, each `[audit]`-flag-gated and self-extinguishing ([docs/self-evolution.md](docs/self-evolution.md#audit-rule-registry)).
- **Settlement ledger** — `reconcile_settled_verdicts` (`[audit] settlement_reconciler_enabled`) upserts settled PRs into `settled_verdicts.jsonl`, sparing the phantom rules a merge-oracle call ([docs/self-evolution.md](docs/self-evolution.md#settlement-ledger)).
- **Forced arms** — audit rules pair detection with an actuator; 'delivered' stamps from a ledger re-read, never the send return ([docs/self-evolution.md](docs/self-evolution.md#forced-arms--detection-paired-with-delivery)).
- **Record-time outcome binds** — `maestro/outcome_authority.py` authors every landing verdict (`success` iff landed); `maestro/outcome_grounding.py` keeps only actuators over git and host facts, including `bind_costume_discharge_to_partial` (`[loop] frame_discharge_bind_enabled`) ([docs/self-evolution.md](docs/self-evolution.md#record-time-outcome-binds)).
- **Fetch-before-word gate** — `gate_remediation_verdict` downgrades to `partial` a verdict that claims a push is owed without ever looking at git (`[fetch-missing]`), or asserts ownership without the `record_obligation_fork_truth` read (`[fork-missing]`) ([docs/self-evolution.md](docs/self-evolution.md#fetch-before-word-gate)).

## Testing Principles

Unit tests must rely on mocking so they:
- **Never use real system services or processes** — mock subprocesses, signals, OS-level APIs
- **Never write to the file system** — use the `mem_fs` fixture for all file I/O; a write under a production `memory_dir` is refused and fails its test via the `tests/_live_state_fence.py` audit hook
- **Never make real network calls** — mock HTTP clients, API calls, external services
- **Never use real `sleep`** — patch `asyncio.sleep` / `time.sleep`
- **Never open long-lived connections** — mock WebSockets, SSE streams, and similar
- **Test logic in isolation**
- **Unambiguous assertions** — never use ternary expressions or complex operator chains in `assert`; prefer simple `assert x == y` comparisons
- **Per-test runtime gate** — `pytest-timeout`: 5s unit, 15s `@pytest.mark.component`, 60s `@pytest.mark.browser`; override only when justified; preferred fix is mocking the slow dependency.
- **Adversarial fault-seeding** — seed faults via in-memory mutation, detected by `exec` divergence + `ast`/regex (not subprocess) (`tests/test_fault_seeding.py`).

Component tests share the "no real network" rule. Browser tests use `create_router()` for their server fixture. Tests must exercise fallback and guard branches, not just happy paths. See [docs/testing.md](docs/testing.md).

## Quality Gates

All code must pass before merging. CI enforces.

```bash
python3.14 -m ruff check maestro/ tests/ scripts/ && python3.14 -m mypy maestro/ scripts/ && python3.14 -m pytest tests/ -v
python3.14 -m pytest tests/browser/ -v -m browser --no-cov --browser chromium
python3.14 -m ruff check maestro_review/ tests/test_maestro_review/ && python3.14 -m mypy maestro_review/ && python3.14 -m pytest tests/test_maestro_review/ -v --no-cov
(cd maestro_sdk && python3.14 -m ruff check src/ tests/ && python3.14 -m mypy src/ && python3.14 -m pytest tests/ -v)
```

| Gate | Tool | Threshold |
|---|---|---|
| Lint | ruff | Zero errors |
| Types | mypy | Zero errors |
| Tests | pytest | All pass |
| Coverage | pytest-cov | 100% |
| Browser | playwright | All pass |
| Per-test runtime | pytest-timeout | 5s unit / 15s component / 60s browser |

`maestro gate-check` (`maestro/gate_check.py`) is the on-demand aggregate: it runs ruff+mypy+pytest, prints a per-gate breakdown, and exits `0` iff all pass; `--full` widens it to match what CI checks by also running the two sibling packages' gates (`maestro_review/`, `maestro_sdk/`) into the same aggregate — CI stays authoritative. ## Evolution Protocol

**Before changing:** read this file, then use plan mode. Keep each evolution small and focused — one thing well. Build on what works: when a recent successful task branch fits, set `source_task_id` and pick `task_followup` priority.

**While changing:** new functionality must include tests (bugs need a failing test first, using `mem_fs` and mocked externals). Main-phase SDK calls must be session-attached. Keep the journal honest — evolution notes capture *why*, not just what.

**Before committing:** self-review every modified file for leftover debug code, missing error handling, inconsistent naming, and dead code. `ruff check`, `mypy`, and `pytest` must be green (coverage = 100%, plus browser tests); CI enforces this, and `.claude/quality-gate-hook.sh` is an opt-in Stop hook you can register in `.claude/settings.local.json`. Update CLAUDE.md *only* if an invariant changed — constants, prose, and incident history belong in code or `docs/`. The commit message explains the why, not just "fix tests".
