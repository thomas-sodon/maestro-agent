## Description

> Status updated to shipped on 2026-08-09 by /update-proposals — see [README.md](../README.md#shipped) for the landing record.

Today the loop lets the model narrate a task or remediation outcome in prose, then runs a large detection-and-correction apparatus to catch the cases where that prose lies about whether a PR actually landed. Two halves fight the same failure: an *affirmative half* (`outcome_grounding`) that binds a narration-derived verdict back to git-truth at record time, and a *detective half* (the phantom / narration audit rules) that flags when the recorded verdict contradicts merge-truth. Both exist only because the model is trusted to report its own result and then caught when it doesn't.

This proposal inverts the arrangement. The task/remediation verdict becomes a pure function of observed git-truth — computed at record time from the already-existing merge-truth chokepoint (`MaestroAgent.is_pr_settled`, proposal 087) and the mechanical push/landing sensors — and the model's prose is never read back as a status signal. Once the verdict is never derived from prose, there is nothing for the affirmative binds to correct and nothing for the phantom rules to detect: both collapse into one small actuator.

The end state is a single mechanical outcome authority that owns the landing verdict, a descriptive-only model summary that no sensor parses, and a standing measurement of the phantom-landing rate so the retirement of the detection layer is evidence-backed rather than asserted. This is not new observation — the git-truth this consumes is already computed today; it is a rewiring of *who is allowed to author the verdict*.

## Relevant Findings

- `maestro/outcome_grounding.py` (`ground_landing_claim`, `bind_diagnostic_success_to_landing`, `bind_self_committed_success_to_landing`, `bind_self_committed_partial_to_landing`, `neutralize_unlanded_resolution_narration`) — the affirmative half: each is a record-time bind that downgrades/upgrades a narration-derived verdict against git facts, and each is a named patch for a specific observed hallucination. `bind_mergeable_flip_to_merge_request` in the same module is *not* a narration-correction — it is a genuine actuator (a mergeable-flip merge request) and must be preserved, not deleted.
- `maestro/audit_checks.py` (`check_phantom_remediation`, `check_phantom_resolution`, `check_phantom_escalation`, `check_unconfirmed_own_landing`, `check_narration_verdict_mismatch`) — the detective half: deterministic rules that flag when the recorded verdict contradicts merge-truth. `outcome_grounding`'s module docstring already frames itself as "the affirmative half" of `check_narration_verdict_mismatch` — the same predicate implemented twice under separate flags.
- `maestro/narration_cues.py` (`RESOLUTION_KEYWORDS`, `RESOLUTION_RE`, `RESOLUTION_MARKERS`, `SELF_COMMITTED_SHA_RE`) — the prose-matching vocabulary the sensors read from a task's narration. A keyword matcher over the model's own prose is exactly the coupling this proposal removes.
- `maestro/agent.py` (`_record_remediation_outcome`, `run`) — where the verdict is composed today; the binding of narration to verdict is the densest comment region in the module and carries per-incident PR-number archaeology.
- `maestro/remediation_tracker.py` (`gate_remediation_verdict`, `measure_unlanded_remediations`, `resolve_push_delivery_marker`) — the fetch-before-word floor and the unlanded-remediation sensor already compute the mechanical git-truth (fetch + `--is-ancestor`, HEAD-vs-`origin/<branch>`); the actuator consumes these rather than inventing a new observation.
- `maestro/agent.py` (`MaestroAgent.is_pr_settled`) delegating to `maestro/world_state.py` (`observe_pr_merge_truth`) — the provenance-stamped, fetch-first, per-iteration merge-truth chokepoint (proposal 087). `is_pr_settled` is the method the verdict authority calls; it is defined on `MaestroAgent` in `maestro/agent.py`, not in `world_state.py`, and forwards to the module-level observer there. The chokepoint already exists, so this is wiring, not new perception.
- `maestro/prompts/remediation.py` (`merge_truth_first_preamble`) — the remediation prompt already forces `git fetch` + `git merge-base --is-ancestor` before any status word. That the prompt must command the model not to lie is itself the proof that prose is untrustworthy; this proposal finishes the job by not reading the prose at all.
- No standing metric exists for phantom-landing-claims per N tasks. The detection apparatus is tuned by individual incident (the `*_first_seen.json` sidecars, per-issue flags), never against a measured base rate — so no one can say whether it is over- or under-built.

## Risk Assessment

The verdict is trust-chain-adjacent: it decides `success` / `partial` / `failure`, which feeds rejection learning, the version archive, and escalation. The dominant risk is a false `partial` on a genuinely-landed PR — but the actuator reads the *same* `is_pr_settled` chokepoint that already governs settlement everywhere else, so it cannot be more wrong about landing than the system is today; it only removes a second, prose-derived opinion that can disagree with it. Rollback posture: `[loop] mechanical_outcome_authority_enabled` stays default-off through Steps 1–2, and shadow-mode parity must be demonstrated before the Step 3 cut-over. No schema change occurs through Step 4; Step 5 removes `Config` fields, so mirror the stale-field-drop guard used when proposals 085/098 retired fields. Because Steps 4–5 only delete code that fires on a now-impossible input, each is self-extinguishing — the parity metric from Step 2 is the objective signal that the deletions are safe.

## Out of scope

- The merge-truth chokepoint itself (`is_pr_settled`, proposal 087) is reused unchanged; this proposal does not alter how landing is *observed*, only who authors the verdict from it.
- The remediation *prompt* preamble (`merge_truth_first_preamble`) can be simplified once prose is never read, but that cleanup is deferred to avoid coupling the prompt change to the verdict rewiring.
