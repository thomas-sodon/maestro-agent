## Description

Every give-up mechanism in the remediation path keys on the *PR's* head SHA and is blind to the other side of the race: `origin/main`. `_is_stalled_remediation_lineage` counts consecutive `partial` laps carrying the same `pr_head_sha` and concludes "externally blocked, unchanged work." For a conflicting PR that inference is wrong. A head that did not advance may mean the resolution could not land while the base moved underneath it — a materially different world, not an unchanged one. The loop treats "I did not win" as "nothing changed," and retires work that has never actually been re-attempted against the world it now faces.

This matters because a moving base is the *normal* condition for any contributor to this repository, not an exception. `origin/main` gained 33 commits on 2026-07-18 and 45 on 2026-07-19 — roughly 35–45 a day, comfortably more than one lap's worth. A recurring conflict hotspot compounds it: `tests/test_claude_md_brevity.py`, whose lockstep `_MAX_LINES` / `_MAX_WORDS` caps and append-only comment ledger make two concurrent PRs conflict whenever both touch it, appears in 13 of the last 60 merge commits (~22%). That is a frequent aggravator, not a universal one — the thesis rests on base velocity, which alone outruns a lap. Reconciling against a base that moves faster than one lap is not an anomaly to be engineered away — it is the job. A contributor that stops when the base moves cannot contribute at all. The current design encodes the opposite instinct in three places at once: the stall predicate ignores base movement, `_in_conflict_cooldown` bounces Tend off a conflicting PR for `conflict_resolution_cooldown_hours` regardless of how far the base travelled during it, and `assess_pr_salvage` reads a large `commits_behind` as licence to disengage — making *falling further behind* a reason to quit rather than a reason to run.

The change makes base advance a first-class re-entry signal. A lap records the base SHA it raced against alongside the head SHA it produced; every stop condition is re-keyed from the head alone to the pair `(pr_head_sha, base_head_sha)`. A moved base breaks the stall streak, invalidates the conflict cooldown, and clears the behind-budget disengage — because the prior attempt raced a base that no longer exists. Repeated failure against the *same* base still stops the loop, at the same cap, for the same reason it always did: that is genuinely unchanged work.

The end state: Maestro re-enters the resolution race whenever the base moves, exits only when it has failed repeatedly against a base that stood still, and — when it cannot win a race it keeps re-entering — escalates that fact to Thomas as an explicit unwinnable-race signal rather than dissolving into a silent stand-down. As a direct consequence the current production deadlock dissolves: PR #3112 is un-poppable today only because a stall keyed on its frozen head outlived 78 commits of base movement.

## Relevant Findings

- `maestro/agent.py` (`_is_stalled_remediation_lineage`) — counts consecutive `partial` laps whose `pr_head_sha` equals the current origin head, capped by `STALLED_REMEDIATION_LAP_CAP` (2). The docstring reads the streak as "a PR the loop has re-serviced *cap* times without the head advancing — externally blocked, unchanged work." There is no base input: the predicate cannot distinguish a frozen world from a lost race.
- `maestro/agent.py` (`_first_non_stalled_pr_index`) — returns `None` when every `pending_pr_requests` entry is stalled, documented as falling "through to the self-directed queue." With a single-entry FIFO and `wip_primacy` blocking `generate_task` on the same PR, that fallback is closed and the entry becomes unreachable — the live deadlock.
- `maestro/memory.py` (`TaskRecord.pr_head_sha`) — the per-lap delivery watermark. There is no companion field recording the base the lap raced against, so base movement is unrepresentable in task history and no consumer can key on it.
- `maestro/evolution.py` (`_in_conflict_cooldown`) — bounces Tend off a conflicting PR while `conflict_resolution_cooldown_hours` (24.0) has not elapsed since `last_conflict_resolution_attempt_at`. Head-advance invalidates the cooldown (#2821); base-advance does not. A 24h cooldown spans roughly 40 commits of base movement at current velocity.
- `maestro/pr_facts.py` (`assess_pr_salvage`, `RECONCILE_COMMITS_BEHIND_BUDGET`) — a `branch_conflicting` PR measured strictly past a behind-budget of 10 resolves to `Salvage.DISENGAGE_PERMITTED`, lifting 094's veto on `gh pr close`. This encodes distance-behind as grounds for disengagement — precisely inverted for a repository whose base moves ~40 commits/day.
- `maestro/pr_facts.py` (`observe_pr_staleness`, `PrStaleness.commits_behind`) — already measures the branch against `origin/main` from local git with no host-API or SDK input, so this proposal reuses the seam 095 established rather than opening a new one. It does not, however, already yield a SHA: the observer takes exactly two injected oracles (`commits_behind_fn` → `int`, `merge_clean_fn` → `bool`), and `commits_ahead_behind` returns a pair of ints. A base SHA therefore needs a third injected oracle — `CodeHost.rev_parse(ref) -> str | None` already exists and is the natural reuse, resolved against `origin/main` in the `EvolutionEngine._observe_pr_staleness` adapter that owns the ref string. Still local git, still no host-API or SDK call, but a genuine signature change.
- `maestro/prompts/remediation.py` (`MERGE_TRUTH_FIRST_PREAMBLE`) — instructs `git fetch` + `--is-ancestor` as action zero and treats a non-zero ancestry result as licence to proceed, but carries no instruction to push the reconciliation *before* spending turns on full local gates. Live laps ran ruff/mypy/pytest to green before pushing, which is long enough at current base velocity for the merge to go stale between resolution and push.
- `tests/test_agent_remediation_gates.py` — covers the stall predicate against head-SHA variation only; no case advances the base while holding the head fixed, so the misinference this proposal fixes is currently untested in either direction.

**The race was run, and the pushes landed (`maestro.log`, 2026-07-18).** PR #3112's origin head advanced `1211e86f → e13d62a6 → 48c76222` across the laps. The agent merged `origin/main`, resolved the conflict, ran gates green, committed, and pushed successfully. The failure is not resolution and — post-096 — not delivery.

**The base outran the lap.** `origin/main` gained 33 commits (07-18) and 45 (07-19); laps take ~45–75 minutes, so the base moves several commits per lap on average. #3112 stands 59 commits behind with a single conflicting file, `tests/test_claude_md_brevity.py` — a file carried by 13 of the last 60 merge commits (~22%), which at this velocity is enough to re-conflict a resolution within a lap. Each resolution was correct when made and stale before it settled.

**The stop conditions all fired on the wrong key.** The stall predicate counted three same-head `partial` laps and froze the entry while the base moved 78 commits. `_in_conflict_cooldown` held Tend off #3112 until 2026-07-19T11:29 across the same span. At 59 behind, `assess_pr_salvage` now returns `DISENGAGE_PERMITTED` — the further behind the PR falls, the more the system authorises abandoning it.

**One turn per lap is spent on a false wall.** A lap emitted `git push origin HEAD 2>&1 | tail -12`, was denied by the action gate (the bare-`HEAD` form 096 did not fold into its conformance set — `_dest_ref("HEAD")` is not in the owned set), and narrated *"The push is blocked by the human-in-the-loop action gate — a task-executor may not push to an evolve branch"* before recovering with the `HEAD:<branch>` form, which succeeded. The lost turns are minor; the belief is not — it feeds the stand-down reasoning downstream.

Deadlock regression: a single-entry `pending_pr_requests` whose only member is same-head-stalled but base-advanced must be poppable by `_first_non_stalled_pr_index` — the direct guard against the production stall recurring. ## Risk Assessment

**The real risk is unbounded re-entry.** Keying re-entry to base movement means a repository this active can re-admit a PR almost every lap, and a genuinely unwinnable PR could consume remediation budget indefinitely. Three bounds contain it: the same-base cap still stops unchanged work at `STALLED_REMEDIATION_LAP_CAP`; the existing burn-rate throttle (`[loop] max_loop_budget_usd_per_hour`) already gates the heaviest phases and is unchanged; and step 8 converts a persistently lost race into an explicit escalation. The rollout and its tripwires are in *Falsifiability* below.

**Interaction with 092 and 094 is the point, not a side effect.** This proposal deliberately loosens two guards those proposals tightened. It does not remove them: `wip_primacy` still blocks discretionary generation, and 094 still vetoes disengagement from salvageable work. What changes is that neither can any longer be satisfied by a stall that outlived its own premise. The conjunction that produced the live deadlock is broken at exactly one edge — the stall key — which is the minimum change that restores an escape.

**Push-first must not walk into the red-read bind.** Step 6 trades local verification for time-to-push, and one existing guard reads that trade as dishonesty: `bind_ci_failing_verdict_to_red_read` downgrades a completion-narrating lap on a `CI_FAILING` PR where the CI-failure oracle surfaced a failing-check line and the lap did not commit-and-push a fix. An unscoped push-first instruction would manufacture that shape every time a prior push turned the check red — the lap would push, narrate success, and be scrubbed to `partial` + `[red-unread]`, converting a latency win into a false-stall signal. The carve-out in step 6 keeps the two compatible: push-first applies only to a reconciliation-only lap whose blocker is not red, so the guard and this proposal never contend for the same lap.

**Trust chain untouched.** No approval, sandbox, or merge capability changes. Step 7 widens the action gate's *parsing* of a push destination, not its policy: `main`/`master`, force-pushes, and unowned branches stay denied, and the conformance test asserts each. Rollback for every step is a config flag flip, or `git revert` for the prompt and sensor steps.

## Falsifiability

The design is right if, after `base_advance_re_entry_enabled` defaults on: a conflicting PR whose base has moved becomes poppable within one lap rather than freezing at `STALLED_REMEDIATION_LAP_CAP` (the #3112 shape, guarded by the deadlock regression test); `measure_base_advance_races` from step 9 reports a race-won ratio materially above zero, meaning re-entries convert to landings rather than merely recurring; `measure_confirmed_landing_rate` (CONFIRMED-LANDING-RATIO) rises on conflicting lineages; and `wip_primacy` → `blocked` stops dominating `gate_activations.jsonl` on a single unreachable entry.

It failed if any of these hold instead: the race-won ratio stays near zero while re-entry count climbs — re-entry without convergence, i.e. the unbounded-re-entry risk realised, and the signal to lower the same-base cap rather than keep flipping; step 6's push-first lands more stale-then-red pushes than it saves laps, visible as a rise in `[red-unread]` notes; or remediation budget consumed per landed conflicting PR rises against the flag-off baseline. Ship Phase 2 flag-off, watch the step-9 sensor for one window, and read these tripwires before flipping.

## Out of scope

**Removing the conflict hotspot.** `tests/test_claude_md_brevity.py` appearing in ~22% of recent merges is a real and separately fixable defect — derive the caps or assert growth rather than absolute counts, and drop the changelog-in-source comment ledger. It would make the race easier for every PR at once. It is deliberately excluded here because it treats the symptom this proposal exists to survive: the base will still move, and Maestro must be able to race a moving base whether or not any single hotspot is smoothed. Worth its own proposal, not a substitute for this one.

**098's ownership taxonomy.** Orthogonal and complementary: 098 decides who owns clearing a blocker, this decides when a stop condition has outlived its premise. Neither subsumes the other.
