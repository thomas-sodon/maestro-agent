## Description

> Status updated to shipped on 2026-08-14 by /plan-proposal — see [README.md](../README.md#shipped) for the landing record.

A task carries two shapes: the **frame** — how its goal describes it ("measure", "investigate", "probe") — and the **discharge** — what it actually produced (a tracked production file, a net diff to an existing file, or a recorded reading). Today nothing binds the two. The frame is classified from the goal string alone (`classify_task_shape`), the discharge is recorded in the completed `TaskRecord`, and no code compares them. The consequence is a reflex the running agent has named and cannot grip: it frames a task as investigation and discharges it as construction, because construction is the "safe motion that always succeeds" while a genuine investigation has no defined, loseable deliverable. The agent's own self-model calls this `measurement-costume`, `construction-default`, and `loseability-flight`; it has also correctly diagnosed why every attempted cure has failed — `sensor-not-actuator: I propose passive sensors to cure reflexes only a choice-phase actuator can change`.

Since this investigation was opened, **PR 3429 has landed the choice-phase actuator this proposal's Step 5 anticipated** — `investigation_observable_gate`, a post-call task-gate that, when a generated goal is investigation-framed and commits to creating a new artifact file while naming no observable signal to read, fills `next_task_directive` with a reframe demand. That is the reviewer-prescribed *actuator at the phase where task shape is chosen*, and its arrival confirms this proposal's thesis over the passive-sensor plan it also displaced. But PR 3429 reads only the **frame** — three signals lifted from the goal *string* (an investigation verb, an artifact-creation commitment, the absence of a named observable) — and thereby *guesses* the discharge before the task runs. It never inspects the completed record, so it cannot see a goal that names an observable to clear the gate and then discharges construction anyway, and it cannot cap such a task's `success`. It is the choice-phase half, implemented as exactly the goal-string-only reading this proposal's ledger flags as the recurring structural tell.

This proposal now supplies the missing half and the one owner that binds both sides. `maestro/frame_discharge.py` becomes the single, provenance-stamped source of the `COSTUME` / `MATCH` / `N/A` verdict, computed from what a task actually *discharged* (its completed `TaskRecord`), reusing the existing `classify_task_shape` for the frame side so no rival classifier is born. Its actuator is a **record-time outcome bind** that caps an investigation-framed-but-construction-discharged task at `partial` — removing the guaranteed-win incentive PR 3429 structurally cannot reach, because the record does not yet exist when its gate fires. A single subordinated sensor surfaces the same verdict in `contemplate()`, superseding the pending passive-sensor plan that motivated this investigation. And rather than add a *second* gate racing PR 3429's for the same directive slot, Step 5 folds PR 3429's live gate under the owner: its frame/flee predicate delegates to the owner's `classify_frame`, and it gains a discharge-evidence arm that fires on a *measured* costume — so the choice-phase guess and the record-time truth share one definition and cannot drift.

The end state: the frame↔discharge contract has exactly one owner, AST-enforced; a construction discharge can no longer collect `success` while wearing an investigation costume; and the growing pile of goal-string-only gates and sensors stops accreting — including PR 3429's just-landed choice-phase gate, whose frame predicate this proposal routes through the same owner — because the fact they each half-read now lives in one place that both *observes* the reflex and *acts* on it.

## Relevant Findings

- `maestro/audit_checks.py` (`classify_task_shape`) — classifies a task purely from its `goal` string via `_SHAPE_PATTERNS`, with construction verbs ordered ahead of investigation verbs. It never inspects the completed record, so it cannot see whether an investigation-framed goal was *discharged* as construction. This is the frame side of the contract, and it already exists — the proposal reuses it rather than adding a second classifier, closing the agent's live open question `classifier-keying: what does the construction/investigation behavioral classifier key on`.
- `maestro/audit_checks.py` (`format_task_shape_summary`, `check_construction_dominance`) — both measure the *distribution* of shapes over a window (rule 17 fires when construction ≥ 60%). They read only the goal string and count frames; neither compares a single task's frame to its discharge. Distinct axis — out of scope for retirement, but evidence the goal-string-only reading is already duplicated across sites.
- `maestro/purpose.py` (`compute_investigation_rate`) and `maestro/task_gates.py` (`_investigation_streak_run`, `_investigation_rate_run`) — the streak/rate directive gates push the agent *toward* construction when investigation-framed tasks dominate, to prevent trace-less reading. They are orthogonal to frame honesty and are deliberately preserved; the frame↔discharge check governs whether a *declared* investigation is a real one, not the investigation/construction ratio.
- `maestro/task_gates.py` (`investigation_observable_gate`, `is_investigation_observable_flee`) — **new, from PR 3429.** A post-call gate dispatched from `generate_task`'s enqueue loop (not a `GATE_CHAIN` entry) that fires on a generated goal that is investigation-framed, commits to creating a new artifact file, and names no observable signal, filling the empty `next_task_directive` slot and appending one `gate_activations.jsonl` row. It reads the **goal string only** — the frame plus a goal-string proxy for the discharge — never the completed `TaskRecord`, so it pre-empts a self-announcing flee but is blind to one that clears the gate and discharges construction anyway. This proposal reuses it as the choice-phase actuator (routing its frame predicate through the owner) rather than adding a rival gate, and pairs it with the record-time discharge bind it structurally cannot provide.
- `maestro/outcome_authority.py` (`decide_outcome`, `OutcomeFacts`) — proposal 105's sole author of the *landing* verdict for remediation PRs: `success` iff git shows the branch merged, else `partial`, reading no prose. It applies only when `landing_relevant`; self-directed investigation/construction tasks pass their candidate outcome through untouched, so today a construction discharge under any frame keeps whatever `success` its step/criteria assessment produced.
- `maestro/outcome_grounding.py` (`bind_ci_failing_verdict_to_red_read`) — the house pattern for a record-time actuator that caps `success`→`partial` and appends a bracketed merge-truth note when a git-grounded precondition is violated. The frame-discharge bind is the same shape applied to a different precondition.
- `maestro/memory.py` (`TaskRecord`) — carries every field the discharge classifier needs: `goal` (frame), `branch` (set only when the run produced tracked changes), `artifacts_dir` (the gitignored, ephemeral reading channel), `key_findings`, and `result_summary`. `branch is None` with only `artifacts_dir` writes is a clean investigation; a set `branch` touching `maestro/`, `tests/`, or `docs/` is a construction discharge.
- `maestro/task_gates.py` (`GATE_CHAIN`, `TaskGate`, `run_gate_chain`, `GateContext`) — proposal 069's declarative registry of *pre-call* `directive`-kind gates that fill the empty `next_task_directive` slot (first-writer-wins) before the generation SDK call; `GateContext.recent()` already loads the 10-task window a discharge check needs. PR 3429's `investigation_observable_gate` is instead a *post-call* actuator in `generate_task`'s enqueue loop; Step 5's discharge-evidence arm extends that existing gate rather than adding a registry entry, so the shape gates and the frame-honesty gate stay side by side without a new inline block.
- `maestro/agent.py` (`contemplate`, the `## Measured Behavioral Data` block) — assembles ~14 classifier/measure/format sensor triples. The pending plan proposed a 15th here; this proposal instead has the block read the one owner, so the sensor and the actuators cannot diverge.
- `tests/test_structural_guards.py` — the AST-enforcement house for "one owner, one door" invariants (the merge-truth and CI-truth chokepoints are enforced here). The frame↔discharge sole-owner rule is enforced the same way.

## Prior Point Fixes (whack-a-mole ledger)

Every prior mechanism on the task-shape axis — including PR 3429's newest choice-phase gate — reads exactly one side of the contract: the goal-string frame, or the shape distribution, or the git-landing outcome. None binds a single task's frame to its measured discharge. That is the structural tell, and PR 3429 landing another goal-string-only reader (now at the choice phase) is the same pattern one step earlier, not its resolution.

|---|---|---|---|
| `classify_task_shape` / `format_task_shape_summary` | 069-era | goal string only | Labels the frame; blind to discharge. A costume goal classifies by its investigation verb and is never rechecked. |
| `_investigation_streak_run` / `_investigation_rate_run` | 069 | frame distribution | Pushes *toward* construction; does not police whether a declared investigation is real. Dormant here (windows unfilled). |
| `investigation_observable_gate` (`is_investigation_observable_flee`) | **PR 3429** | goal string (frame + artifact-creation proxy) | The choice-phase actuator this axis lacked — but still one side only: it *guesses* the discharge from the goal before the task runs, never rechecks the record, and is cleared by a goal that merely *names* an observable then discharges construction. **Reused, not retired** — folded under the owner (Step 5) and paired with the record-time bind. |
| `check_construction_dominance` (rule 17) | audit registry | frame distribution | Fires on aggregate ≥60% construction; says nothing about a single task's frame/discharge honesty. |

No existing shipped mechanism is deleted — the streak/rate gates and rule 17 measure a genuinely different axis (distribution) and are preserved, and PR 3429's `investigation_observable_gate` is *reused* (its frame predicate re-homed in the owner, its default-on flag kept as the single master switch), not replaced. The design's contribution is the *missing* owner and the record-time discharge bind, plus bringing PR 3429's choice-phase gate under that owner — not a rival to any of them.

## Risk Assessment

- **False positives punishing honest work.** The discharge classifier keys on *tracked* production files (`branch` + non-`artifacts/` paths), so an investigation that records findings to `artifacts/` or the journal is `MATCH`, not `COSTUME` — the exact distinction the `5aa82f9baf2d` evidence and the `false-clean-report` limitation demand. Both actuators default off, enabled only after the classifier's live incidence is validated against `task_history.jsonl`.
- **Over-suppressing legitimate construction.** The bind fires *only* on an investigation frame paired with a construction discharge; honest construction-framed tasks (`1d9add26174d`) are untouched, and the streak/rate gates that legitimately steer toward landable construction are preserved.
- **Interaction with proposal 105's outcome authority.** The new bind runs on self-directed (non-`landing_relevant`) records, disjoint from `decide_outcome`'s PR-landing domain; the AST guard prevents a second frame↔discharge owner from appearing beside it.
- **Interaction with PR 3429's live gate.** `investigation_observable_gate` and the record-time bind write different surfaces — the choice-phase directive slot vs. the completed task's outcome — so they cannot collide. Step 5 folds the gate's frame predicate into the owner and adds its discharge arm *in place* rather than standing up a second gate on the same slot, and it reuses PR 3429's flag, so no two mechanisms race to fill `next_task_directive`. If PR 3429 is reverted before this lands, the owner + record-time bind + sensor still stand alone (Step 5 then re-introduces the gate as new); if this lands first, PR 3429's default-on gate simply gains the owner-backed discharge arm.
- **Rollback.** Two proposal-owned flags (`frame_discharge_bind_enabled`, `costume_display_enabled`), both default-off, plus PR 3429's existing `investigation_observable_gate_enabled` as the gate's single master switch; steps are independently mergeable with the owner first, so an interrupted rollout leaves current behaviour intact. The pending sensor plan is retired only in Step 4, after the owner it would share is proven.
- **Falsifiability.** If the design is right, the `COSTUME` rate over `task_history.jsonl` falls once the gate and bind are enabled, and investigation-framed tasks stop recording `success` on construction discharge. The design has failed if the `COSTUME` rate stays flat while investigation-framed tasks keep landing `success` — recorded honestly, not reinterpreted, per the agent's own loss-condition discipline.

## Out of scope

- The investigation/construction **ratio** (how often the agent should investigate vs build) — governed by the preserved streak/rate/rule-17 distribution mechanisms, a distinct axis.
- The `OWNED-NET-DELTA` / purpose-scoring pressure that makes construction attractive in the first place — a separate class about how self-directed work is *scored*, not how a task's frame is bound to its discharge.
- Any change to proposal 105's `decide_outcome` landing authority; the new bind is additive and domain-disjoint.
- Tuning PR 3429's goal-string flee heuristic (the investigation/artifact-creation/observable regexes) — this proposal only re-homes its frame test in the owner and adds the discharge arm; the regexes' precision is PR 3429's own falsifiable experiment, and its default-on flag is left untouched.
