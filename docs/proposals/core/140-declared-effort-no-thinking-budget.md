## Description

> **Burn-in.** Partially completed — all behaviour-code has landed and runs behind its flag; what remains is the burn-in observation window, then graduating the flag and decommissioning the retired logic. See [README.md](../README.md#status-key).

The operator wants four things. Maestro should run on Claude Opus 5.5. Every SDK call should run at `low` effort except self-review (`high`), evolution planning (`medium`) and plan refinement (`medium`). Thinking should scale with effort. And self-review should run in a session separate from the implementation it reviews. Each of these could be done as a scattered edit, and that is how every earlier change to the same settings was done. That approach is the problem. **The failure class:** a call's thinking policy is spelled out by hand at each call site and at each session opener, instead of being worked out once from what the call declares and what the model supports. The policy covers which model runs, at what effort, with what thinking budget, and on whose session. Because it is hand-spelled, every model bump or effort retune becomes a scattered edit, and each missed site fails silently. It silently runs at an inherited effort, with a thinking cap the SDK ignores, or at the model's own default.

Today the live tree has 37 hand-written `effort=` literals and five `thinking_budget_tokens=128_000` literals. It also has a global 10K budget that is applied the same way to `low` and `high` calls. The installed Agent SDK (0.2.149) documents `max_thinking_tokens` as deprecated, and on adaptive-thinking models it is "treated as on/off (0 = disabled, any other value = adaptive)". So the 10K-vs-128K split that three fixes and seven tests maintain has no effect on the model. On Opus 5.5 a fixed thinking budget is rejected outright (400), and **effort is the only thinking control**. So "scale thinking with effort" needs no budget: on every model Maestro can select, the declared effort already *is* the thinking depth. The budget knob is deleted rather than re-scaled. Opus 5.5's default effort is also `medium`, where Opus 4.8's is `high`. Every caller that declares no effort would therefore change behaviour silently on the bump. `execute_step` is one of them: $— of production spend in the window. The self-review part of the request is the same class seen from the session side. A turn on a shared session runs at the session's creation-time effort. So once the implementation lineage moves to `low`, a same-session self-review cannot run at `high`, whatever its call site says. Separating the sessions is the only way the declared effort can take effect.

The remedy builds on 139's call-owned policy registry and adds the two facts 139 did not own. First, a **model profile registry** (`maestro/model_profiles.py`) is the single owner of model facts: id, default effort, supported efforts, and pricing. It admits only models that take adaptive thinking with effort, so selecting a budget-only model such as Haiku 4.5 fails at config load instead of silently running without thinking. Second, a **policy resolver at the SDK seam** takes each call's effort from `CALL_POLICIES`. Every call sends `thinking={"type": "adaptive"}` with that effort. **The thinking budget is deleted outright**: the `[sdk]` key, the module global, the `QueryOptions` field, its validator, the five 128K literals, and cli_paced's `MAX_THINKING_TOKENS` mirror. Effort becomes mandatory at the seam, so no call reaches a provider without one. A declared **session-lineage consistency** invariant (every member of a shared session has its opener's effort) makes self-review's separation structural rather than a convention. Under the operator's tiers, `self_review` (`high`) cannot legally share `implementation_session` (`low`). It becomes a `SINGLE_USE` call through 139's seam, still carrying the plan's action-gate hooks. When this lands, the model switch is a two-line edit (`DEFAULT_MODEL` plus `[models] default`). An effort retune is a one-line tier edit. There is no thinking budget left to write.

## Relevant Findings

- `maestro/sdk.py` (the Anthropic option mapping in the query path) passes `options.effort` through as `sdk_opts["effort"]`. When any effort is set, it adds `sdk_opts["max_thinking_tokens"] = options.thinking_budget_tokens or _sdk_thinking_budget_tokens`, so a `low` call and a `high` call get the same 10,000-token cap unless a call site hard-codes 128K. No `thinking` option is ever sent.
- Installed `claude_agent_sdk` 0.2.149 (`ClaudeAgentOptions.max_thinking_tokens` docstring, read in the loop container): "deprecated — Use `thinking` instead. On newer models, this is treated as on/off (0 = disabled, any other value = adaptive)." The transport emits `--thinking adaptive` for `thinking={"type": "adaptive"}` and `--effort <level>` for `effort`. So on Opus 4.8 today, `thinking_budget_tokens` only acts as "thinking on". That is also why it can't simply be dropped: on Opus 4.8 and 4.7, leaving out `thinking` runs the model *without* thinking. The non-zero budget is what currently switches thinking on for every call that sets an effort, and `thinking={"type": "adaptive"}` is its exact replacement.
- Budget-only models are not in use. `maestro.toml` sets `[models] fallback = ""` and `long_context = ""`, so every call runs on `claude-opus-4-8`. The OpenAI provider already ignores the budget and maps effort to `reasoning.effort`.
- Opus 5.5 API facts (claude-api reference, 2026-09): `{"type": "enabled", "budget_tokens": N}` and `{"type": "disabled"}` return 400 at every effort level. Effort (`low`/`medium`/`high`/`xhigh`/`max`) is the only control, and its **default is `medium`**. Pricing is $4 / $20 per MTok input/output and $0.20 cache read. The 1M context window is the default. Forced `tool_choice` returns 400, but Maestro sets no `tool_choice` or sampling parameters (`grep` over `maestro/`).
- `maestro/sdk.py` (`QueryOptions.__post_init__`) range-validates a per-call budget (fix `3aa00e18`, #1170), and `maestro/providers/cli_paced.py` (`_thinking_env`) mirrors the budget into the CLI child's `MAX_THINKING_TOKENS`. The two providers disagree on the default: Anthropic applies the module-global 10K, while cli_paced applies nothing. So there are two re-implementations of a knob the model ignores. `maestro_sdk` exposes no thinking or effort spawn flag. Once the env mirror goes, cli_paced does what it already does for every call without an explicit budget, which is all but five sites: it follows the CLI's own thinking config.
- `maestro/config_settings.py` models `[sdk]` with `extra="forbid"`. When the key is deleted, an overlay that still sets `thinking_budget_tokens` fails at config load rather than being silently ignored.
- Hand-spelled effort sites. The session openers are `maestro/agent.py` (`_build_contemplation_session_options`: `high`/128K; the evolve session: `high`/128K, `caller="evolution_session"`; `_curate_pending_plans`: `high`/128K, `caller="curate_session"`; the implementation phase's `impl_session`: `high`, no budget), `maestro/loop/lifecycle.py` (`open_run_session`: `medium`) and the task-generation, artifact-review and doc-proposals session openers. The one-shot arms are in `maestro/evolution.py`, `maestro/consciousness.py`, `maestro/purpose.py`, `maestro/dreaming.py` and `maestro/planner.py`. `maestro/executor.py` (`execute_step`, both the session and stateless options) declares **no** effort.
- `maestro/agent.py` (implementation phase) opens `impl_session` and then calls `self.evolution.self_review(plan, base_hash, session=impl_session)` under the comment "Self-review in the SAME session — reviewer sees full implementation conversation context". `converge_to_green` then runs `auto_fix` on the same session.
- `maestro/evolution.py` (`self_review`): on the session path it prepends the fence "You are now reviewing the implementation you just completed", while the prompt body it prepends to says "You are reviewing an evolution implementation in a fresh context". The stateless arm already builds complete review options (`allowed_tools`, `mcp_servers`, `disallowed_tools`, `cwd`, long-context `model`/`betas`, `hooks=self.action_gate_hooks(plan)`, `phase="implementation"`), so the review needs nothing from the transcript.
- `maestro/sdk.py` (`_note_session_effort_override`) is called at 17 sites. It logs at DEBUG when a session turn carries an effort, and never compares the two.
- The model id is written in `maestro.toml` (`[models] default`, two `[sdk.pricing."claude-opus-4-8…"]` tables), `maestro/config.py` (`sdk_model` default, a seven-row `sdk_pricing` default that duplicates the TOML), `maestro_review/sdk.py` (`REVIEW_MODEL`), `docs/sdk-internals.md` and four test modules. The Opus 4.8 pricing row reads $15 / $— / $1.50 / $18.75. The published Opus 4.8 rate is $5 / $25.
- `maestro/flag_lifecycle.py` (`EXPERIMENTAL_FLAGS`, `CUTOVER_FLAGS`) is the house flag-lifecycle registry these steps use.
- Proposal 139 (`CALL_POLICIES`, `CallPolicy(effort, thinking_budget_tokens, tools, phase, scope)`, `single_use_call`, the step-5 AST guard) supplies the registry and the single-use seam. It explicitly defers Session C ("the reviewer shares the implementer's transcript"). This proposal takes on that deferral for `self_review` only, and it **drops** 139's `CallPolicy.thinking_budget_tokens` field. There is no budget to declare (step 5).

## Risk Assessment

- **Implementation quality at `low` effort.** This is the operator's directive. It is also the largest risk: the reference guidance says coding and long-horizon agentic work respond strongly to effort on this model family. The caller is not the only thing that moves. `implement_plan`, `auto_fix` and `execute_step` together carry $— of the window's spend. *Tripwire:* over step 8's window, if the share of implementation attempts demoted to `failed` or abandoned by `classify_attempt` rises more than 10 points against the pre-flip window, or `auto_fix` rounds per implementation double, move `implement_plan` and `auto_fix` to `medium`. That is one tier edit, and step 3's consistency test forces `implementation_session` to move with them.
- **Planning quality at `medium`.** *Tripwire:* the rejection rate rises above 20% (baseline 14.8%, 97/657), or `measure-dead-on-arrival-mints` rises against its pre-flip reading. Either moves `PLANNING` to `high`.
- **Deleting the budget.** Step 5 relies on the Agent SDK's documented contract that a non-zero `max_thinking_tokens` means adaptive thinking on this model family. The one real hazard runs the other way: dropping the budget *without* sending `thinking={"type": "adaptive"}` would switch thinking off on Opus 4.8, so the test pins the adaptive option on every call that sets an effort. *Failure signal:* per-caller output tokens and cost on metered rows (step 2's telemetry), compared over 3 days either side of step 5, move by more than noise. That would mean the SDK treated the old values as more than on/off. Roll back by reverting step 5; it is one PR.
- **Lost review context.** A fresh reviewer loses the implementer's reasoning, which is the point of the change. The prompt already carries the plan, the acceptance criteria and the full diff. The reviewer keeps its tools and can read anything else.
- **Preserved thinking on Opus 5.5.** Opus 5.5 ties thinking blocks to an unedited conversation prefix. The Agent SDK keeps the prefix intact, and Maestro's specialised-prompt prepends go into new user turns, not edits to history. Single-use sessions (139 plus step 6) shrink the exposure further. *Failure signal:* any 400 mentioning thinking or block binding in `logs/maestro.log` after step 9. Roll back with the one-line model revert.
- **Pricing correction moves the throttle.** Once step 9 removes the stale TOML rows, estimated rows are priced lower, so the burn-rate throttle (`[loop] max_loop_budget_usd_per_hour`) admits more work per hour. The operator should re-read the budget knob at step 9. That is intended, but it should be a deliberate decision.
- **Rollback.** Steps 1–4 and 6–7 are inert with their flags off (step 1 changes only the unused default). Step 5 is unflagged but behaviour-preserving, and reverts as one PR. Steps 8 and 9 are single config reverts. Step 10 lands only after both windows hold.

**Falsifiability.** The design is right if:
1. After step 8, every production cost-sample row carries its caller's tier effort and none reads `default`, where today `execute_step`'s 3,725 calls send none.
2. The self-review first-round LGTM rate falls from **89.8%** (88/98). The share of LGTMs made with zero tool calls falls from **65.9%**. Self-review context p50 falls from **137.5K** to the size of its prompt (plan + diff).
3. The share of approved heads that then go red at the gate falls from **75%** (66/88) below 50%.
4. Production $/day falls from the **$—/day** baseline while the planning and implementation tripwires hold.

If (2) holds and (3) does not, the reviewer's misses were not caused by the shared context. The next remedy is the review prompt requiring the local gate to run before an LGTM, not more session machinery. If (4) fails because tripwires force tiers back up, the directive's tiering, not the resolver, was wrong, and the resolver makes that a one-line correction.

## Out of scope

- **`maestro_review/`'s `REVIEW_MODEL`.** It lives in a separately installed package that cannot import `maestro.model_profiles` (packaging boundary, `tests/test_packaging_boundary.py`). Bump it as a one-line follow-up in that package. Its effort policy is its own.
- **`[models] long_context` and `LONG_CONTEXT_BETA`.** On models whose default context is already 1M, the beta header and the separate `[1m]` pricing label may be vestigial. That needs its own measurement.
- **Output-token undercount on estimated rows.** Estimated `cost_samples.jsonl` rows show a p50 of 5 output tokens even for calls that plainly wrote thousands. The early-exit estimator does not count streamed output, which is a separate telemetry defect.
- **Per-message effort** (the Opus 5.5 `mid-conversation-output-config` beta) would let a shared session vary effort per turn and relax step 3's consistency rule. The Agent SDK does not expose it today.
- **Transcript sharing in sessions A, run and rejection.** That is 139's deferred scope. Under these tiers every one of those lineages is uniform `low`, so step 3 passes without touching them. The rejection pair's high/low split (`4999806c`) loses its reason, but collapsing it back into one session re-opens 139's cross-plan-bleed question and is left to that follow-up.
- **Budget-only models.** Haiku 4.5 and pre-4.6 models get no profile, so they cannot be selected. Adopting one later means deliberately reintroducing a budget for that model, not reviving a global knob.
- **A thinking switch on cli_paced.** `maestro_sdk` has no `--thinking` / `--effort` spawn option, so cli_paced calls follow the CLI's own config. Adding one is spawn-option parity work (proposal 077's territory).
- **`xhigh` / `max` efforts.** No tier uses them. The profile's `efforts` field admits them, so adopting one later is a tier edit.
