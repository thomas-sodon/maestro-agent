Full module-by-module reference. Linked from [`CLAUDE.md`](../CLAUDE.md).

| Module | Purpose |
|---|---|
| `maestro/consciousness.py` | Self-model with capped list/string fields, identity prompt. See [self-evolution.md](self-evolution.md) for audit integration. Carries the proposal-129 `SelfModel.claim_evidence` map (one resolved-citation entry per `capabilities_known` claim, keyed by `claim_key`'s concept-token fold so a re-worded claim keeps its evidence) — populated by `update_self_model` behind `[audit] evidence_bound_claims_enabled`, pruned + capped self-extinguishingly in `save_self_model`, coerced fail-closed on load/import, and omitted from the update prompt while empty so the flag-off prompt is byte-identical. The claim-grounding fold over this map is surfaced read-only by `maestro consciousness-report` (the perceptual-grounding row). |
| `maestro/conscious_workspace.py` | Conscious-access workspace leaf owner (proposal 130; wired behind the observe-only `[loop] conscious_workspace_observe_enabled` flag). The closed vocabularies (`TrustClass`, `SourceKind`, `ExclusionReason`, `ContinuityKind`), the frozen bounded record shapes (`WorkspaceItem`, `ExcludedCandidate`, `AttentionSchema`, `ConsciousMoment`, `BroadcastReceipt`, `ConsciousEpisode` — every collection a `tuple` so records stay hashable and immutable), the hard content bounds, and the sole `build_workspace_item` constructor that head-truncates a summary to `MAX_ITEM_SUMMARY_CHARS` and refuses (raises `ValueError`) any summary tripping `secret_scan.has_hard_block` so a credential can never be persisted. `SourceKind` now spans ten owners: the four operationally-decisive additions `pr_focus`, `queue_pressure`, `budget_state` and `prediction_verdict` sit beside the original six, with matching `_SOURCE_ACTIONABILITY` rows ranking `pr_focus` above `audit_finding`, `queue_pressure` at the `task_outcome` level, `prediction_verdict` between `task_outcome` and `self_model`, and `budget_state` lowest. Owns the two moment identity hashes — `compute_candidate_hash` over the full considered set and `compute_selection_hash` (the broadcast identity) over the admitted set plus schema, both canonicalising like `memory.compute_plan_content_hash` — and the append-only episode ledger behind a `ConsciousEpisodeBackend` protocol with the `JsonlConsciousEpisodeLedger` default (append under `file_lock`, newest-first reads via `iter_jsonl_reverse` with bounded corrupt-record skipping) and explicit tuple-coercing round-trip (`episode_to_dict` / `_parse_conscious_episode_dict`). Also owns the pure, versioned **attention policy** (`ATTENTION_POLICY_VERSION`, weights, and the `TrustClass`/`SourceKind` provenance tables): `score_candidate` (five weighted terms; trust and actionability from provenance, novelty from source identity, exponential age decay), `select_workspace_items` (the ordered exclusion rules — expired → untrusted → duplicate-source dedup → reserved human slot → rank-and-admit under the caps, each stamping an `ExclusionReason`), and `assemble_moment` / `derive_moment_id` composing selection → `build_attention_schema` → `build_conscious_moment` into a deterministic moment; the policy calls no gate (attention is not authorization). A leaf module: imports only the standard library plus `fileutil` and `secret_scan`, so `state_store.py` can import it without a cycle. The loop assembles and persists a moment only from `agent._phase_attend`, behind that observe-only flag; see [conscious-access.md](conscious-access.md) for the claim vocabulary and indicator matrix. |
| `maestro/workspace_candidates.py` | Candidate adapters for the conscious-access workspace (proposal 130), the non-leaf sibling of `conscious_workspace.py`. One pure adapter per observation owner — `candidates_from_human_directives` (`SelfModel` operator queues → `authenticated_human`), `candidates_from_diagnostics` (a `DiagnosticSnapshot`'s error/quota/rate-limit/consecutive-failure/cost-trend facts → `mechanical_observation`, the cost fact reusing `diagnostics.is_rising_high_cost`), `candidates_from_audit_findings` (an `AuditResult`, keyed on `AuditFinding.rule`), `candidates_from_task_outcomes` (recent `TaskRecord`s), `candidates_from_self_model` (open questions / limitations / `next_task_directive` → `agent_derived`), `candidates_from_pr_focus` (the `wip_primacy.TaskFocus` owned-PR verdict plus each `pr_facts.LivePlan` with an open PR — a `Discretionary` verdict and a plan's LLM-authored `rationale` both contribute nothing), `candidates_from_queue_pressure` (a `QueuedTask` queue's depth against `Config.task_queue_max` and its FIFO head, mirroring `loop.task_generation`'s `free_slots` arithmetic), and `candidates_from_budget_state` (the agent's plain in-process burn-rate / maintenance throttle booleans, naming *which* constraint is in force), and `candidates_from_prediction_verdicts` (the scored reflection bets `audit_checks_calibration.load_scored_reflection_bets` yields, admitting only a bet stamped `verdict_source == "measured"` — the calibration oracle's authorship is the trust warrant, so a `narrated` self-grade contributes nothing — keyed on `prediction_id` and observed at the bet's own timestamp) → `mechanical_observation` — each returning `list[WorkspaceItem]` built through the leaf's `build_workspace_item`, with `gather_candidates` concatenating all nine in one fixed order (the four new owners appended after the original five, each defaulting to an empty contribution so a caller omitting them gets the previous ordering). Also owns the two attend-phase seams the loop calls instead of open-coding them: `load_prediction_verdict_inputs` (the named read over `audit_checks_calibration.load_scored_reflection_bets`) and `declare_blind_spots` (the `AttentionSchema.blind_spots` vocabulary — the always-omitted owned-WIP focus plus one entry per owner that contributed nothing, the prediction owner declaring two distinct gaps: an empty scored-bet ledger, and a ledger holding only `narrated` self-grades). Trust is fixed by which owner produced a candidate, never by its summary text; imports no network/git/subprocess and references no gate symbol (attention is not authorization). Registered in `audit_checks._MODULE_FAMILIES`. |
| `maestro/consciousness_eval.py` | Offline evidence reader over the conscious-episode ledger (proposal 130) — the pure fold that grounds all six of the consciousness-report's global-workspace indicators (previously `not_implemented`) in mechanical facts. `WorkspaceVerdict` (`not_observed` / `architectural` / `behaviorally_supported` / `refuted`); six frozen counts-bearing readings (`LimitedAccessReading`, `ReceiptedBroadcastReading`, `RecurrenceReading`, `SchemaAgreementReading`, `TemporalContinuityReading`, `CausalReachReading`, mirroring `audit_checks_calibration.PremiseReport`); and the six pure evaluators `evaluate_limited_access` (folds each moment's selection trace — admitted-vs-excluded competition, and cap/hash violations: `schema.capacity_used` or admitted count over `max_items`, summed admitted-summary length over `max_chars`, or a stored `selection_hash`/`candidate_hash` disagreeing with a recomputation via `compute_selection_hash`/`compute_candidate_hash`) and `evaluate_receipted_broadcast` (folds each episode's receipts — coverage of `CONSCIOUS_CONSUMERS`, with an integrity violation for an unauthorized consumer or a `moment_hash` disagreeing with the moment's stored `selection_hash`), `evaluate_recurrence` (folds each moment's lineage-bearing items — recurrence fires when a verified `task_outcome` re-enters carrying `WorkspaceItem.lineage`, with a provenance violation for any lineage-bearing item not sourced `task_outcome` / `mechanical_observation`), `evaluate_schema_agreement` (folds each moment's `AttentionSchema` against its trace — `capacity_used` == admitted count, `omitted_count` >= recorded exclusions, `capacity_used` within `max_items`), `evaluate_temporal_continuity` (folds each moment's continuity marker — a `genesis` moment names no predecessor, a non-genesis one names a predecessor or carries a typed gap), and `evaluate_causal_reach` (folds each moment's validated decision citations — `cited_task_ids` / `cited_plan_ids` — against the citing consumer's delivery receipt, with a provenance violation for cited plans lacking an `evolution` receipt or cited tasks lacking a `task_generation` one; scored with `fired=False` so *declared* decision uptake is capped at `architectural` — the matrix reserves `behaviorally_supported` for a counterfactual ablation). All six score through the shared `_score` ladder (empty → `not_observed`; any violation → `refuted`; present-but-unexercised → `architectural`; else `behaviorally_supported`); there is no total consciousness score and no reading reads any free-text (eloquent self-report cannot raise a reading, corrupt provenance refutes it). A leaf: imports only from `conscious_workspace`. Pure, zero SDK cost, no I/O — surfaced read-only by `maestro consciousness-report` via `cli._consciousness_reading`. Registered in `audit_checks._MODULE_FAMILIES`. |
| `maestro/counterfactual_probe.py` | Interventional-sensitivity probe over the conscious-access workspace (proposal 130) — the operator-run instrument behind `maestro workspace-counterfactual`, and the one CLI surface that reaches the provider. Owns the versioned scenario pack (`COUNTERFACTUAL_PACK_VERSION`, the frozen `ItemSpec` / `CounterfactualScenario` records, and the three-scenario `COUNTERFACTUAL_SCENARIOS` tuple — the declarative shape of `self_calibration.CONSCIOUSNESS_CRITERIA`, with every consumer taking `scenarios=None` so a test injects its own pack), the matched-pair construction `build_conditions` (one `ConsciousMoment` admitting the decisive item, one ablating exactly it, both assembled at the same `assembled_at` through `conscious_workspace.build_workspace_item` / `assemble_moment` so the pair is reproducible), and `render_condition` / `build_prompt`, which render through the sole formatter `conscious_workspace.render_active_moment` and normalise the moment id and `selection_hash` out of the prompt — both derive from the admitted set, so left visible they would hand the ablated condition an unattributable "something was removed" cue. Scores with the frozen counts-bearing `TrialOutcome` / `ScenarioResult` / `CounterfactualReport` (the `consciousness_eval.CausalReachReading` shape) via `score_scenario` / `score_pack`, folding `follows_decisive` / `ablation_shifts` / `false_citations` / `unparsed` / `measurement_gaps` into **two** independent readings on the shared `consciousness_eval.WorkspaceVerdict` ladder — sensitivity (no pairs → `not_observed`; any shift → `behaviorally_supported`; else any measurement gap, or no `comparable_pairs` — pairs both of whose sides parsed — at all → `not_observed`, so an all-unparsed run reads as a failed measurement rather than a substantive no-effect finding; else `architectural`) and `citation_integrity` (any false citation → `refuted`) — scored apart so one stray hallucinated id cannot bury a genuine shift under a non-deterministic provider, with a false citation judged through `conscious_workspace.validate_citation` and the gap through `decisive_is_visible` over `conscious_workspace.visible_item_ids`, rather than a private re-derivation. A scenario whose decisive item never became visible in the full condition is recorded as a measurement gap, never read as a negative result: both conditions would render identical content, so its zero tests no intervention. Drives the trials through the injectable `SessionSeam` (`default_session_seam` binds it to `sdk.create_session` / `query_on_session` / `disconnect_session` with `tools=[]`, `max_turns=1`, one ephemeral session per condition torn down in a `finally`), so the bare-`query()` structural guard needs no allowlist entry and a test drives a fake with no provider reached. Mutates no state: no episode or decision ledger is written, no elicited decision is executed, and the report's counts-only payload carries no prompt text, model prose, or item summary — its provider calls are metered like every other one, so app log, transcript sidecar and `cost_samples.jsonl` rows are written, and `MAX_REPEATS` bounds how many calls the CLI will bill. Deliberately does **not** lift the causal-reach indicator's `architectural` cap — folding results into `consciousness-report` is later work, kept separate so that command's offline no-SDK guarantee stays untouched. Registered in `audit_checks._MODULE_FAMILIES`. |

| `maestro/gate_convergence.py` | Pure gate-convergence predicate + result type (proposal 110): `plan_next_round(prev_failures, curr_failures, *, all_clean, rounds_used, ceiling, prev_count, curr_count, truncated)` decides `green`/`continue`/`stuck` from the *failing set* movement (`all_clean` → green; ceiling reached → stuck; either side's enumeration capped (`truncated`) → continue iff the full-enumeration count fell; strict shrink → continue; else stuck). Green binds to per-gate CLEAN status, not an empty `curr_failures` (proposal 124), and the failure sets carry *failure-identity* signatures (one position-free `GateRunObservation.progress_signature` member per failing test/diagnostic — ruff/mypy keys drop the line so a fix that shifts a survivor is still progress, #4309) when the caller supplies an observation, coarse gate labels otherwise (`evolution_quality._progress_signals` is the seam that picks between them off `[loop] gate_observation_enabled`). Its self-review sibling `plan_next_review_round(*, approved, made_changes, rounds_used, ceiling, gate_clean, verify_grace_remaining)` decides the same three outcomes from per-round review signals (`approved` → green; ceiling reached → stuck; `made_changes` → continue; `gate_clean and verify_grace_remaining > 0` → continue — a bounded verify-only round against a provably-green branch; else stuck), so an approval and the ceiling both still outrank the proposal-124 grace and the loop always terminates. `ConvergenceResult` carries the orchestrator's outcome plus the proposal-124 `attribution` verdict. Zero I/O, zero SDK (`QualityGateResult` is a type-only reference); driven by `evolution_quality.converge_to_green` and routed unconditionally into `implement_plan` (proposal 110 retired the `[loop] gate_convergence_enabled` rollout flag). |

| `maestro/evolution_fuel.py` | Gap issues, the evolution-fuel owner (proposal 155 Step 1). A closed owner-id grammar (`parse_owner_id`: `maestro:gate`, `maestro:source_budget:<path.py>`, `maestro:toolchain:<need>`, `capability:(act_kind|completion_check):<name>`), each prefix mapped by `GAP_PREFIXES` to one `gap:*` label and its admitted openers. `open_gap_issue` is the one opener door (idempotent per owner id; refuses an operator hand-closed issue as `operator-abandoned`, including one a non-operator reopened, and a door issue whose gap label or title was edited away as `gap-tampered`; writes a `gap_opens` row in `gaps.db` on each open or reopen), `close_gap_issue` the one closer, and `classify_gap_trust` / `admit_gap_issues` admit only issues an operator (`[evolution_fuel] operator_github_logins`) labelled or that a `gap_opens` row re-derives, recording every other one as `gap-unverified` through `Journal.record_event`. `operator_login_refusal` backs the `_build_agent` startup check. Step 2 adds the zero-SDK self-health detectors, run by `run_self_health_detectors`: `observe_red_main` folds an origin/main check-run read into the one `red_main_watch` row (the first-red clock, restarted when the set of failing check names changes, never by a mid-run read whose failures the row already holds) and `detect_red_main` opens `maestro:gate` past `[evolution_fuel] red_main_grace_hours` and closes it only on a green read no live inherited hold pins; `open_gate_for_inherited_hold` opens or reuses that issue for a proposal-124 hold (its seam is inert while `[loop] evolve_every` is `0`); `detect_source_budget` keeps at most one `maestro:source_budget:<path>` issue open, for the worst file (an empty scan closes nothing) at or over the split budget (up to `SOURCE_BUDGET_MAX_OPEN_ATTEMPTS` candidates past refusals). Step 4 adds fuel selection: `select_evolution_fuel` (one unfiltered open-issue read, trust admission through `_admit_with_trust`, live-plan / attempt / cooldown skips, class-1-only while a gap plan awaits review, lowest `fuel_class_of` first) returning a `FuelSelection`, and the pure, `GAP_CONTEXT_CAPS`-bounded `render_gap_block`. Step 5 adds the stuck-gap tripwire: a gap at the cap is labelled `needs-decision` (`NEEDS_DECISION_LABEL`, never fuel) and returned in `FuelSelection.tripped`, its count restarted from the label's latest removal; `render_gap_decision_task` / `format_gap_decision_ask` / `parse_gap_decision_question` / `parse_gap_decision_reply` / `apply_gap_decision` render, deliver and apply Thomas's build/buy/drop choice (`GAP_DECISION_TIERS`). Pinned by the `gap_issue_owner` structural guard, which also covers `red_main_watch`. |

| `maestro/call_policy.py` | Declarative per-caller SDK call policy (proposal 139). `CALL_POLICIES` maps every live `caller` tag reaching `QueryOptions` / `query` / `query_on_session` to a frozen `CallPolicy` (effort, a required named `surface` from `tool_surface.NAMED_SURFACES`, provider phase, `SessionScope` `SINGLE_USE` / `SHARED`), seeded from each call site's stateless-arm literals; the evolution-lineage callers and `self_review` are `SINGLE_USE`. Surfaces (proposal 142): the contemplation lineage declares `REFLECTION_READ_ONLY`, the implementation callers (`implementation_session`, `implement_plan`, `auto_fix`, `self_review`, `execute_step`) `REPO_MUTATING`, and every other caller `TOOL_FREE`; the evolution single-use policies take `TOOL_FREE` and provider phase (`evolution`) from the evolution slot they run on today. `single_use_call` enforces only a tool-free surface (`tools=[]`); a built-in-bearing one keeps the caller's `options.tools`, which the seam derives from the surface under `[sdk] enforced_tool_surface_enabled`. `single_use_call` is the registry's first reader: it opens a session with the caller's policy, sends exactly one `query_on_session` turn, and disconnects in `finally`, refusing `SHARED` callers, unregistered ones, any caller whose phase is action-gated (`tool_surface.action_gated_phases()`) unless per-call `options` carry the action-gate hooks, and `options` whose effort or caller disagrees with the policy, before any session opens; `self_review` routes through it with the plan's hooks under `[loop] self_review_own_session_enabled` (default-off); the evolution-lineage callers route through it under `[sdk] single_use_evolution_calls_enabled` (default-off), ignoring any passed session and keeping slot B's `OBJECTIVE_PROMPT` framing via `evolution_slot_system`. Under the same flag the loop opens no slot-B session at all, so `evolve` / `curate_pending_plans` hand their callers `session=None`. Beside the registry sit two declarations no seam reads yet (proposal 140): `EFFORT_TIERS` / `TIER_EFFORT` (review `high`, planning and refinement `medium`, default `low`; `tier_of` / `tier_effort`) and `SESSION_LINEAGES` (each shared-session opener and the callers riding it, whose tier efforts and `effective_surface`s must agree — surfaces compared at both groundings when the opener's surface is runtime-grounded). `tests/test_call_policy.py` keeps the registry complete against the tree via `ast`. |
